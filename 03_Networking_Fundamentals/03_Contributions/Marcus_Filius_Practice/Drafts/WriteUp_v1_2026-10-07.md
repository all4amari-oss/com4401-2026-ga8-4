## First draft built from his answers + his Filius evidence

### Client and server

In our network, the Staff PC was the client and the Library Server was the server. The Staff PC asked for the website and the Library Server provided it. Before that, the Staff PC pinged the server at 192.168.20.10 to check it could reach it, and got 4 replies back with 0% packet loss. The Library Server held the page, index.html, and ran the webserver, so it was the one with something to give.

### Why did ping use fewer layers than loading the web page?

The ping was just a quick knock on the door. ICMP only needed the Network and Internet layers to ask "are you there?" and get a reply. The web page needed more of an interaction. First the Staff PC and the server did the 3 handshakes with TCP (SYN, SYN/ACK, ACK) on the Transport layer, then HTTP asked for the page and sent it back on the Application layer. Each layer wraps up the message from the layer above it, which is called encapsulation, so the more a task needs, the further up the layers it goes.
